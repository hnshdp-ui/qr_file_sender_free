# 播放控制与手动补发

运行 `run_sender.cmd "文件夹路径" --fps 8` 后，直接打开二维码窗口。窗口初始暂停，只显示一张静态文件信息二维码。先在手机开始接收、固定位置，再点击 PC 窗口的“播放”；播放中可点击“暂停”。调整窗口大小不会重建任务。

## 编号规则

- `0`：文件信息帧 META，每次出现内容相同，收到一次即可。
- `1～N`：原始 DATA 分片，N 为发送端显示的 Source symbols。
- 编号固定，不是当前轮的第几张画面，也不是累计播放次数。补偿帧显示单独的块/方程标识，不占原始分片编号。
- 旧块编号从 0 开始：`B/S` 对应新编号 `B × block_size + S + 1`。例如默认块大小 64 时，`B5/S11` 对应 `332`。

正常播放仍先发送全部原始分片，再发送补偿分片。原始分片在不同块之间交错，因此窗口显示的原始编号不一定连续。

## 从指定编号开始

在 PC 输入一个编号，例如 `332`，点击“从编号播放”。立即切换、自动播放，先发送 META，然后按编号播放 332～N，再播放补偿帧并循环；循环仍保持此模式。输入 `0` 则从 META 和全部原始分片开始，原始分片按编号顺序播放。

## 只补缺片

手机“缺失二维码编号 / 手动补发”显示全部尚未恢复的原始编号，相邻编号合并为范围。例如 `12,35-38,332`。输入 PC 后点击“仅补发列表”，只循环发送这些原始分片及文件信息帧。支持逗号、中文逗号、分号、空格及范围；输入不合法时显示错误，不中断现有播放。

手机如果没收到 META，会显示缺失编号 `0`；此时还不知道总分片数。输入 `0` 点击“仅补发列表”可持续显示 META。收到 META 前的数据帧不会缓存，需要随后再接收。收到 META 后，缺失列表会自动改为原始数据编号。META 已收到时无需反复手工补它；源数据都恢复后也无需补齐补偿帧。

补发沿用当前任务的文件、分片配置和 Session ID，不会重新打包。保持 PC 窗口和手机页面，勿退出 PC 重开任务、刷新手机或点击“重新接收”。手机暂停摄像头会保留进度。

手机不会自动反馈 PC；列表由用户照着输入。收到少量补发分片后，已有混合方程可能顺带恢复其他缺片，因此列表会实时缩短。收齐后自动 SHA-256 校验，成功后可保存文件。

更新部署目录中的 `receiver-standalone.html` 后，重启接收服务器并在手机上重新打开页面。服务器在启动时读取页面内容，建议在开始新任务前更新。
