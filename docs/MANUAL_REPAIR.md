# 播放控制与手动补发

运行 `run_sender.cmd "文件夹路径" --fps 8` 后，直接打开二维码窗口。窗口初始暂停，只显示一张静态文件信息二维码。先在手机开始接收、固定位置，再点击 PC 窗口的“播放”；播放中可点击“暂停”。调整窗口大小不会重建任务。

## 编号规则

- `0`：文件信息帧 META，每次出现内容相同，收到一次即可。
- `1～N`：原始 DATA 分片，N 为发送端显示的 Source symbols。
- 每个编号始终对应同一个文件分片。
- 旧块编号从 0 开始：`B/S` 对应新编号 `B × block_size + S + 1`。例如默认块大小 64 时，`B5/S11` 对应 `332`。

正常播放时，每轮先显示文件信息帧 `0`，再按 `1 → 2 → … → N` 播放原始分片，期间定期插入文件信息帧 `0`。

## 从指定编号开始

在 PC 输入一个编号，例如 `332`，点击“从编号播放”。先发送 META，再按编号播放 332～N 并循环。输入 `0` 会从 META 开始循环播放全部原始分片。

## 只补缺片

手机“缺失二维码编号 / 手动补发”会把连续的缺失编号合并成范围，如 `12,35-38,332`。将列表输入 PC 并点击“仅补发列表”，即可循环播放这些原始分片和文件信息帧。支持逗号、中文逗号、分号、空格及范围。输入有误时，窗口会显示提示并继续当前播放。

手机如果没收到 META，会显示缺失编号 `0`。在 PC 输入 `0` 并点击“仅补发列表”可持续显示 META。手机从收到 META 后开始记录数据分片，缺失列表会自动更新。

补发沿用当前任务的文件、分片配置和 Session ID，不会重新打包。保持 PC 窗口和手机页面，勿退出 PC 重开任务、刷新手机或点击“重新接收”。手机暂停摄像头会保留进度。

手机每收到一个缺失分片，就会从列表中移除对应编号。收齐后自动进行 SHA-256 校验，校验通过后可保存文件。

更新部署目录中的 `receiver-standalone.html` 后，重启接收服务器并在手机上重新打开页面。服务器在启动时读取页面内容，建议在开始新任务前更新。
